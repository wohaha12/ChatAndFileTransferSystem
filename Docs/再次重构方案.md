### **阶段一：构建系统修正 (CMake Fixes)**

**目标**：解决 `Common` 库链接错误，确保所有模块在 Windows 下正确引用 Qt6。

#### 1. 修改 `Common/CMakeLists.txt`
`INTERFACE` 库不能包含源文件（.cpp）。必须改为 `STATIC` 库，并正确开启 Qt 自动化。

```cmake
# 文件路径: Common/CMakeLists.txt
cmake_minimum_required(VERSION 3.16)
project(Common)

set(CMAKE_CXX_STANDARD 17)
set(CMAKE_AUTOMOC ON) # 关键：因为 Utils 里可能有 QObject

find_package(Qt6 REQUIRED COMPONENTS Core Network)

# 1. 修改 Protocol 子目录
add_library(CommonProtocol STATIC
    Protocol/TransHeader.h
    Protocol/CommandTypes.h
    Protocol/ProtocolBodies.h
    # 如果有 .cpp 文件也加在这里
)
target_link_libraries(CommonProtocol PUBLIC Qt6::Core Qt6::Network)
target_include_directories(CommonProtocol PUBLIC 
    ${CMAKE_CURRENT_SOURCE_DIR}/Protocol
)

# 2. 修改 Utils 子目录
add_library(CommonUtils STATIC
    Utils/MemoryPool.cpp
    Utils/MemoryPool.h
    Utils/PathUtil.cpp
    Utils/PathUtil.h
    # ... 其他文件
)
target_link_libraries(CommonUtils PUBLIC Qt6::Core)
target_include_directories(CommonUtils PUBLIC 
    ${CMAKE_CURRENT_SOURCE_DIR}/Utils
)
```

#### 2. 修改 `Client` 和 `Server` 的链接方式
在 `Client/CMakeLists.txt` 和 `MetaServer/CMakeLists.txt` 中，确保链接的是具体的静态库名。


### **阶段二：网络层跨平台统一 (Architecture)**

**目标**：移除 `StorageServer` 中所有 Linux 独有的 `epoll` 代码，替换为 Qt6 原生网络模块。

#### 1. 清理 StorageServer 网络层
*   **删除**：检查 `StorageServer/Network/TcpServer.cpp`，如果有 `#include <sys/epoll.h>` 或 `epoll_create`，直接删除该文件内容。
*   **重写**：使用 `QTcpServer` 实现。Qt 在 Windows 上会自动使用 IOCP（性能极高），在 Linux 上自动使用 Epoll。

**修改方案 (`StorageServer/Network/TcpServer.h`)**：

```cpp
#pragma once
#include <QTcpServer>
#include <QTcpSocket>
#include <QThreadPool>
#include "../../../Common/Protocol/TransHeader.h" // 引用协议头

class TcpServer : public QTcpServer {
    Q_OBJECT
public:
    explicit TcpServer(QObject *parent = nullptr);
    bool start(quint16 port);

protected:
    // 重写此函数处理新连接
    void incomingConnection(qintptr socketDescriptor) override;
};

// 处理具体业务的 Runnable (放入线程池，避免阻塞主线程)
class ClientTask : public QRunnable {
public:
    ClientTask(qintptr descriptor);
    void run() override;
private:
    qintptr m_socketDescriptor;
};
```

**修改方案 (`StorageServer/Network/TcpServer.cpp`)**：

```cpp
#include "TcpServer.h"

void TcpServer::incomingConnection(qintptr socketDescriptor) {
    // 方案：将 socket 丢给线程池处理，或者在主线程利用信号槽异步处理
    // 为了利用 Qt6 的性能，推荐使用信号槽非阻塞模式，而不是每个连接一个线程
    // 这里演示最简单的信号槽模式（单线程 Reactor，适合 Windows 开发调试）
    
    QTcpSocket *socket = new QTcpSocket(this);
    if (socket->setSocketDescriptor(socketDescriptor)) {
        connect(socket, &QTcpSocket::readyRead, [socket]() {
            // 处理数据读取...
        });
        connect(socket, &QTcpSocket::disconnected, socket, &QTcpSocket::deleteLater);
    }
}
```

### **阶段三：协议安全与健壮性 (Security)**

**目标**：修复已知的安全漏洞。

#### 1. 修复路径遍历攻击 (Path Traversal)
在 `StorageServer` 接收文件上传请求时，必须清洗文件名。

**修改位置**：`StorageEngine.cpp` 或处理 UploadReq 的地方。

```cpp
#include <QFileInfo>
#include <QDir>

// 在处理 UploadReq 时：
QString rawFileName = QString::fromUtf8(req.file_name);

// 安全修复：强制剥离路径，只取文件名
QString safeFileName = QFileInfo(rawFileName).fileName(); 

// 进一步检查：确保没有 ".."
if (safeFileName.contains("..")) {
    // 拒绝请求，返回错误
    return false;
}

// 使用 safeFileName 进行后续存储路径拼接
```

#### 2. 修复缓冲区溢出 (Buffer Overflow)
在所有使用 `strcpy` 的地方，替换为安全的字符串拷贝。

**修改建议**：在 `Common/Utils/StringUtil.h` 中增加安全拷贝辅助函数。

```cpp
// Common/Utils/StringUtil.h
static void safeCopy(char* dest, const std::string& src, size_t destSize) {
    if (destSize == 0) return;
    // 确保最多拷贝 destSize - 1 个字符
    size_t length = std::min(src.size(), destSize - 1);
    std::memcpy(dest, src.c_str(), length);
    dest[length] = '\0'; // 强制结束符
}

// 使用示例 (在业务代码中)：
// strcpy(res.error_msg, "Some error"); // 危险！
StringUtil::safeCopy(res.error_msg, "Some long error message...", sizeof(res.error_msg)); // 安全
```

### **阶段四：并发与性能优化 (Performance)**

**目标**：解决 MetaServer 被 Redis 阻塞的问题。

#### 1. Redis 异步化/线程池化
由于 `hiredis` 的同步 API 会卡住 Qt 的主事件循环，我们需要将 Redis 操作扔到后台线程。

**修改方案 (`MetaServer/Cache/RedisManager.cpp`)**：

使用 `QtConcurrent::run` 来执行耗时的 Redis 操作。

```cpp
#include <QtConcurrent>
#include <QFuture>

// 示例：异步获取 Token
QFuture<bool> RedisManager::validateTokenAsync(const QString& token) {
    return QtConcurrent::run([this, token]() {
        // 这里是原来的同步代码，现在运行在线程池中
        std::lock_guard<std::mutex> lock(m_mutex);
        // ... redisCommand(GET ...)
        return true; // 或 false
    });
}
```

在 `MetaServer` 调用处，使用 `QFutureWatcher` 监听结果：

```cpp
// MetaServer.cpp
void MetaServer::handleUploadRequest(...) {
    auto future = m_redisManager->validateTokenAsync(token);
    auto watcher = new QFutureWatcher<bool>();
    
    connect(watcher, &QFutureWatcher<bool>::finished, [this, watcher, socketDescriptor]() {
        if (watcher->result()) {
            // Token 有效，继续处理
        } else {
            // Token 无效，发送错误
        }
        watcher->deleteLater();
    });
    
    watcher->setFuture(future);
}
```

### **阶段五：运维基础设施 (Logging)**

**目标**：在 Windows 和 Linux 下都能看到带时间戳、线程ID和级别的日志。

#### 1. 实现简单的日志系统
利用 Qt 的 `qInstallMessageHandler` 全局接管 `qDebug()`。

**新增文件 `Common/Utils/Logger.h` / `.cpp`**：

```cpp
// Common/Utils/Logger.cpp
#include <QMessageLogContext>
#include <QDateTime>
#include <QFile>
#include <QTextStream>
#include <QMutex>
#include <iostream>

static QMutex g_logMutex;
static QFile* g_logFile = nullptr;

void myMessageOutput(QtMsgType type, const QMessageLogContext &context, const QString &msg) {
    QMutexLocker locker(&g_logMutex);
    
    QString txt;
    QString timeStr = QDateTime::currentDateTime().toString("yyyy-MM-dd HH:mm:ss.zzz");
    
    switch (type) {
    case QtDebugMsg:    txt = QString("[Debug] %1").arg(msg); break;
    case QtWarningMsg:  txt = QString("[Warn ] %1").arg(msg); break;
    case QtCriticalMsg: txt = QString("[Error] %1").arg(msg); break;
    case QtFatalMsg:    txt = QString("[Fatal] %1").arg(msg); break;
    case QtInfoMsg:     txt = QString("[Info ] %1").arg(msg); break;
    }

    QString finalMsg = QString("%1 %2 (%3:%4)\n")
            .arg(timeStr, txt, context.file, QString::number(context.line));

    // 输出到控制台 (Windows CMD / Linux Terminal)
    std::cout << finalMsg.toStdString();
    
    // 输出到文件
    if (g_logFile && g_logFile->isOpen()) {
        QTextStream out(g_logFile);
        out << finalMsg;
    }
}

void InitLogger(const QString& filePath) {
    g_logFile = new QFile(filePath);
    if (g_logFile->open(QIODevice::WriteOnly | QIODevice::Append)) {
        qInstallMessageHandler(myMessageOutput);
    }
}
```

在 `main.cpp` (Client/Meta/Storage) 中调用：
```cpp
int main(int argc, char *argv[]) {
    QApplication a(argc, argv);
    InitLogger("application.log"); // 初始化日志
    // ...
}
```
